# 테크노관 층별 실내지도 설계

작성일: 2026-08-23
대상: 금오공과대학교 테크노관 (61번 건물) B1F~6F
목표: 네이버지도 서울역 실내지도처럼 층을 나눠 보는 실내지도를 GUMAP에 적용

---

## 1. 배경과 문제 정의

### 1.1 이미 있는 것

`GUMAP-프론트/js/map/map-techno-indoor.js` (606줄)에 IMDF(OGC/Apple Indoor Mapping
Data Format) 기반 실내지도 모듈이 구현되어 있다.

- B1F~6F 층 선택 패널
- 줌 17 이상에서 실내 상세, 줌 14~16에서 건물 외곽, 줌 13 이하 숨김
- 방 검색, 방 클릭 팝업, 길찾기 목적지 연동
- IMDF 표준 구조: venue / building / level / unit / opening / occupant / anchor

즉 **층 전환 UI 골격은 이미 완성되어 있다.**

### 1.2 실제 문제: 도형이 가짜다

`GUMAP-학교지도/data/imdf/techno/unit.geojson`의 366개 공간 폴리곤을 검사한 결과:

- **366개 전부가 정확히 5점 폴리곤** (닫는 점 포함 = 사각형)
- 전부 동일한 방위각 26.6°로 회전된 직사각형
- 실제 도면의 꺾인 벽, 계단실, 아트리움 형상이 전혀 반영되지 않음

건물 외곽선(`footprint.geojson`)도 64.6m × 95.8m 평행사변형인데, 도면 실측은
**90,200mm × 88,700mm**의 중정형(ㄷ자) 블록이다. 드론 정사영상 위에 겹쳐 확인한
결과 현재 외곽선은 실제 건물과 뚜렷하게 어긋난다.

`GUMAP-학교지도/CAD파일/CAD_(테크노관))/*.dxf` 역시 실제 CAD가 아니다. 레이어명이
`ROOMS` / `CORRIDORS` / `DEPT` / `TAGS` / `DECORATORS` / `HEADER`이고 엔티티 수가
IMDF 유닛 수와 정확히 일치한다. 같은 합성 데이터를 DXF로 되뽑은 산출물이다.

### 1.3 속성 데이터는 정상이다

`GUMAP-학교지도/엑셀정보(방 상세정보)/테크노관_방_정보.xlsx`가 방 속성의 원본이다.

- 시트 7개: `TB1F`, `T1F`, `T2F`, `T3F`, `T4F`, `T5F`, `T6F`
- 컬럼: 방번호 / 이름 / 학과 / CK-1 / 지방대학특성화사업 / 산학융합연구실 / BK21 / LAB30
- 총 361개 방, 방번호 형식 `T_B101`, `T201`, `T305-1`

`GUMAP-학교지도/data/kumoh_techno_rooms.json`(361건)은 이 엑셀의 충실한 export이며
`raw_id`가 엑셀 방번호와 1:1 대응한다. 한글은 정상 UTF-8로 저장되어 있다.

**따라서 이 작업은 실내지도를 새로 만드는 것이 아니라, 속성은 그대로 두고
도형만 실제 도면 기반으로 교체하고 좌표를 다시 잡는 작업이다.**

| **계** | **300** | **66** | **361** | **280** | **81** |

**엑셀 361개 방 중 280개만 도형이 있고, 81개는 지도에 아예 존재하지 않는다.**
누락된 방은 주로 화장실·샤워실(138, 139, 155, 208, 228, 244, 327, 344, 429, 448 등)과

### 1.5 진짜 원본: 도면 PDF

`GIS_DATA/금오공과대학교_학교_설계도/양호동캠퍼스/테크노관/도면만_있는_파일/`에
PDF 12개가 있다. 벡터가 아닌 **스캔 래스터**(JPEG, 2340×1654 ≈ 200dpi)이지만
층별로 깨끗한 평면도가 모두 존재하고 방 번호와 한글 이름이 판독 가능하다.

| 층 | 원본 파일 | 페이지 (0-based) | 도면상 방번호 범위 |
|-----|-----------|-------|-----------------|
| B1F | `테크노관B1F~2F.pdf` | 0 | B101~B133 |
| 1F  | `테크노관B1F~2F.pdf` | 1 | 101~160 |
| 2F  | `테크노관2층.pdf` | 0 | 201~265 |
| 3F  | `테크노관3층.pdf` | 0 | 301~367 |
| 4F  | `테크노관4,5층.pdf` | 0 | 401~466 |
| 5F  | `테크노관5.6층.pdf` | 0 | 501~526 |
| 6F  | `테크노관5.6층.pdf` | 1 | 601~607 |

핵심 성질: **7개 층 도면이 전부 동일한 치수 그리드를 공유한다.**
전체 치수 90,200 × 88,700(mm)이고 칸 분할(9,000 / 2,700 / 7,200 / 4,800 / 2,400 /
7,200 / 4,500 / 2,700 / 7,200 / 7,200 / 7,200 / 7,200 / 6,500 / 300 / 7,200 / 6,500)까지
같다. 따라서 **좌표 변환식 1개로 전 층이 동시에 정렬된다.**

`테크노관B1F~2F.pdf`는 3장짜리이며 B1F(0) / 1F(1) / 2F(2)가 모두 이 공유 도면틀로
작도되어 있다. 페이지 하단 표제(`지하1층 평면도` / `1층 평면도` / `2층 평면도`)로 확인했다.

`테크노관1층.pdf`는 다른 건축사무소(비채) 시리즈로 치수선이 없다. 1층 원본으로
쓰지 않고, 방 이름 교차 확인용 보조 자료로만 사용한다.

### 1.6 자동 추출 타당성 검증 (완료)

OpenCV로 사전 검증했다. 400dpi 렌더링 → adaptive threshold → 방향성
morphological open으로 벽선만 추출하면 **글자가 완전히 제거되고 벽선만 깨끗하게
남는다.** 문 틈을 dilate로 닫고 connected component를 잡으면:

| 도면 | 기준 방 수 | 무보정 자동추출 | 회수율 |
|-----|------:|------:|------:|
| `테크노관2층.pdf` | 61 | 52 | 85% |
| `테크노관3층.pdf` | 65 | 66 | 102% |
| `테크노관1층.pdf` (비채) | 65 | 51 | 78% |

추출된 폴리곤은 실제 벽선에 정확히 붙는다(238·239·240·248·254~259 등 육안 확인).
튜닝과 수동 보정을 거치면 전량 확보가 가능하다.

주의: 세 번째 행은 1층 원본으로 채택하지 않은 비채 도면으로 측정한 값이다.
실제 1F 원본(`테크노관B1F~2F.pdf` p1)의 회수율은 아직 측정하지 않았다.
`102%`는 도면틀 치수선 등을 방으로 오인한 오탐이 섞였다는 뜻이므로,
회수율만이 아니라 오탐률도 함께 관리해야 한다.

### 1.7 좌표 기준자

`GIS_DATA/금오공대_최종산출물/2. 정사영상/`에 드론 정사영상 타일 피라미드가 있다
(EPSG:4326 TMS, z0~17). 서버는 포트 8765, 프론트는 `Ortho4326TmsLayer`로 소비한다.

- 테크노관을 덮는 최고 해상도는 **z16 = 약 0.96 m/px** (z17은 캠퍼스 일부만 존재)
- 타일 인덱스: `x = (lon+180)/360 × 2^(z+1)`, `y = (lat+90)/180 × 2^z` (TMS, y 남쪽 기준)
- 건물 지붕 윤곽이 선명하게 판독되어 모서리 대응점 지정이 가능하다

`GIS_DATA/금오공대_최종산출물/5. 3Dtile/`은 IACF·LIB·StC만 포함하며 테크노관은 없다.

## 2. 결정 사항

브레인스토밍에서 확정된 방향:

1. **전부 벡터화** — 도면 이미지 오버레이가 아니라 실제 방 폴리곤을 추출해
   IMDF 데이터를 진짜로 교체한다. 방 클릭·하이라이트·검색·실내 길찾기가 모두 살아난다.
2. **테크노관 전용** — 다른 건물로 확장할 계획이 없으므로 재사용 파이프라인을
   과하게 일반화하지 않는다. 일회성 작업 스크립트로 처리한다.
3. **브라우저 보정 화면 구축** — 자동 추출이 놓치는 분량을 좌표 숫자로 손보는 것은
   비현실적이므로, 도면 위에서 그리고 고치는 화면을 만든다.

## 3. 설계

### 3.1 대원칙

**`map-techno-indoor.js`는 수정하지 않는다.**

`unit.geojson`의 스키마(`properties.level_id`, `category`, `label.ko-KR`,
`name.ko-KR`, `department`, `research_tags`)를 그대로 유지하면 기존 층 전환·검색·
팝업·길찾기 코드가 손대지 않고 동작한다. 이 제약을 설계 전반의 기준으로 삼는다.

`footprint.geojson` / `level.geojson`의 도형은 실제 외곽선으로 교체하되
`properties` 구조와 `level_id` / `building_ids` 참조 무결성은 유지한다.

### 3.2 산출물 구조

```
GUMAP-개발/floorplan/               # 일회성 작업 도구
  01_extract.py                     # PDF → 방 폴리곤 (도면 픽셀 좌표)
  02_label.py                       # 방 번호 OCR → 폴리곤에 라벨 부여
  03_georef.py                      # 도면 좌표 → WGS84 변환
  04_build_imdf.py                  # 엑셀 조인 → IMDF geojson 출력
  floorplan-editor.html             # 보정 화면
  techno_georef.json                # 층별 좌표 변환 파라미터
  work/
    {floor}_raster.png              # 400dpi 렌더링본
    {floor}_polygons.json           # 도면 픽셀 좌표 폴리곤
    {floor}_labeled.json            # 방 번호 부여 결과
    {floor}_qc.png                  # 검수 이미지 (도면 + 폴리곤 겹침)
    report.json                     # 미매칭 리포트

GUMAP-학교지도/data/imdf/techno/     # 교체 대상 (최종 산출물)
  unit.geojson  level.geojson  footprint.geojson  occupant.geojson  ...

GUMAP-프론트/js/map/map-techno-imdf-data.js   # 위 geojson 번들 재생성
GUMAP-일반지도/map/map-techno-imdf-data.js    # 동일 사본 (아래 3.8 참조)
```

### 3.3 좌표 변환 — 2단계 분리

추출과 좌표를 분리한다. 좌표를 다시 잡아도 폴리곤을 재추출하지 않기 위함이다.

```
도면 픽셀  ──[A: 치수선 기준]──>  건물 로컬 미터  ──[B: 유사변환]──>  WGS84
```

**A단계 (도면 픽셀 → 건물 로컬 미터)**

도면의 치수선 전체값(가로 90,200mm / 세로 88,700mm)과 도면상 픽셀 거리로
스케일을 확정한다. 치수선 양 끝점은 `03_georef.py`에서 사용자가 한 번 지정한다.
7개 층 도면틀이 모두 같으므로 2F에서 한 번 지정하면 전 층에 그대로 적용된다.

주의: 페이지별 렌더링 해상도와 여백이 완전히 동일하지는 않을 수 있다. 층마다
도면틀 기준점(치수선 좌하단 교점)을 검출해 픽셀 오프셋을 보정한 뒤 공유 스케일을
적용한다. 이 기준점 검출 실패 시 해당 층은 수동 지정으로 넘긴다.

**B단계 (건물 로컬 미터 → WGS84)**

유사변환(similarity transform): 회전 θ, 축척 s, 평행이동 t. 어파인이 아니라
유사변환을 쓰는 이유는 건물이 직각을 유지해야 하고, 자유도를 줄여야 소수의
대응점으로도 안정적으로 풀리기 때문이다.

```
[lon]   [ s·cosθ  -s·sinθ ] [x_m]   [t_lon]
[lat] = [ s·sinθ   s·cosθ ] [y_m] + [t_lat]
```

- 대응점은 **정사영상 위 건물 모서리 3~4점을 보정 화면에서 클릭**해 지정
- 최소자승으로 θ, s, t 산출
- **축척 s는 도면 실측으로 교차검증한다.** `s`가 `1.0 ± 0.02`를 벗어나면
  모서리를 잘못 찍은 것이므로 오류로 처리하고 저장을 거부한다
- 위경도 스케일 비등방성은 `lon` 방향에 `1/cos(lat)` 보정을 적용해 흡수한다
  (기준 위도 36.1466)

**층별 적용**

7개 층이 도면틀을 공유하므로 **변환 파라미터는 1세트뿐이다.** 층별 파라미터를
따로 두지 않는다. 다만 층마다 도면틀 기준점 픽셀 오프셋(A단계에서 검출)은
개별 저장한다.

`techno_georef.json` 구조 (값은 3단계에서 산출해 채운다):

```json
{
  "reference_latitude": 36.1466,
  "drawing_extent_mm": { "x": 90200, "y": 88700 },
  "transform": { "theta_deg": null, "scale": null, "t_lon": null, "t_lat": null },
  "control_points": [],
  "floor_origin_px": {
    "B1F": null, "1F": null, "2F": null, "3F": null,
    "4F": null, "5F": null, "6F": null
  }
}
```

`transform`이 `null`인 상태에서는 `04_build_imdf.py`가 실행을 거부한다.

### 3.4 방 번호 매칭

한글 이름은 엑셀에 있으므로 **도면에서는 숫자·`B`·하이픈만 읽는다.** 한글 OCR보다
문자 집합이 훨씬 작아 안정적이다.

1. 원본 래스터에서 텍스트 영역 검출 (벽선 제거 전 이미지 사용)
2. 각 텍스트 영역을 `[0-9B\-]` 화이트리스트로 OCR
3. 폴리곤 내부에 위치한 라벨을 그 방의 번호로 확정
4. 엑셀 방번호를 정규화(`T_B101`→`B101`, `T305-1`→`305-1`)해 조인

**미매칭을 3종류로 분류해 리포트한다.** 이 리포트가 보정 화면의 작업 목록이 된다.

| 유형 | 의미 | 보정 방법 |
|---|---|---|
| `unlabeled` | 폴리곤은 있으나 번호 미인식 | 클릭해서 번호 지정 |
| `missing` | 엑셀엔 있으나 폴리곤 없음 | 도면 보고 직접 그리기 |
| `ambiguous` | 한 폴리곤에 번호 2개 이상 | 선을 그어 분할 |

### 3.5 category 판정

엑셀에는 category 컬럼이 없다. `map-techno-indoor.js`의 `IMDF_STYLE`이 요구하는
카테고리(`laboratory` / `classroom` / `office` / `restroom` / `stairs` / `elevator` /
`walkway` / `utility` / `breakroom` / `library` / `atrium`)를 방 이름 규칙으로 판정한다.

- `강의실`·`대강의실`·`시청각실`·`세미나실` → `classroom`
- `실험실`·`연구실`·`실습실` → `laboratory`
- `화장실`·`샤워실` → `restroom`
- `전기실`·`기계실`·`발전실`·`배기실` → `utility`
- `독서실`·`자료실` → `library`
- `휴게실` → `breakroom`
- 그 외 이름 있음 → `office`
- 엑셀에 이름 없음 → `office` (기존 데이터와 동일한 기본값)

계단·엘리베이터·복도·중정은 엑셀에 없다. 추출된 폴리곤 중 엑셀에 매칭되지 않은
것들 가운데 형상·위치로 판정해 `stairs` / `elevator` / `walkway` / `atrium`을 부여하며,
최종 확정은 보정 화면에서 사람이 지정한다.

## 4. 오류 처리와 검증

### 4.1 파이프라인 단계별 실패 처리

각 스크립트는 실패 시 부분 결과를 남기고 명확히 중단한다. 조용히 잘못된 결과를
내보내지 않는 것이 원칙이다.

| 단계 | 실패 조건 | 처리 |
|---|---|---|
| 01 추출 | 벽선 ink 비율이 비정상 (도면 아님) | 중단, 해당 층 스킵 사유 기록 |
| 01 추출 | 추출 폴리곤 수가 엑셀 방 수의 40% 미만 | 경고 후 계속 (보정으로 처리) |
| 02 라벨 | OCR 결과가 엑셀에 없는 번호 | `unlabeled`로 강등, 리포트 기록 |
| 03 좌표 | 축척 `s`가 `1.0 ± 0.02` 밖 | **오류로 중단**, 저장 거부 |
| 03 좌표 | 대응점 3개 미만 | 오류로 중단 |
| 04 출력 | 엑셀 방 중 도형 없는 것 존재 | 경고 + 목록 출력, 해당 방은 제외하고 생성 |

### 4.2 자동 검증 항목

`04_build_imdf.py`가 출력 직전 수행한다.

- **방 개수**: 엑셀 361개 대비 최종 유닛 수와 누락 목록
- **면적 sanity**: 방 면적이 5㎡ 미만 또는 200㎡ 초과면 경고
- **겹침 검사**: 같은 층 폴리곤끼리 교차 면적이 작은 쪽의 10% 초과면 경고
- **외곽 이탈**: footprint 밖으로 나간 폴리곤 경고
- **층간 정합**: 계단·엘리베이터 중심이 층마다 ±2m 이내인지 확인.
  **좌표 변환이 틀리면 여기서 걸린다.** 이 검사가 가장 중요하다
- **스키마 무결성**: 모든 `level_id`가 `level.geojson`에 존재, 모든
  `occupant.unit_ids`가 `unit.geojson`에 존재

### 4.3 육안 검증

- **층별 QC 이미지** (`work/{floor}_qc.png`): 도면 위에 추출 폴리곤을 겹쳐 그린 이미지.
  방이 벽선에 정확히 붙었는지 한눈에 확인
- **정사영상 대조**: 보정 화면에서 정사영상을 배경으로 깔고 건물 외벽과 폴리곤
  외곽이 일치하는지 확인
- **실제 지도 확인**: `index.html`을 띄워 줌 17 이상에서 층 전환·검색·팝업이
  정상 동작하는지 확인

## 5. 작업 순서

좌표가 틀리면 나머지가 전부 무의미하므로 좌표부터 확정한다.

1. **좌표 변환 확정 (2F 기준)**
   `03_georef.py` + 보정 화면의 대응점 지정 기능을 먼저 만들어
   `techno_georef.json`을 확정한다. 축척 검증과 정사영상 대조로 검수한다.
2. **2F 파이프라인 완주**
   가장 깨끗한 도면인 2F로 01→02→04를 끝까지 돌려 실제 지도에 띄워 확인한다.
3. **보정 화면 완성 → 2F 보정 완료**
   2F를 361개 중 70개 전량 확보 상태로 만든다.
4. **나머지 6개 층 일괄 처리 → 층별 보정**
   전 층이 2F에서 확정한 공유 변환을 그대로 쓴다. 층별로는 도면틀 기준점
   오프셋만 검출해 적용하고, 층간 정합 검사로 어긋남을 확인한다.
5. **IMDF 교체 + 기존 UI 동작 확인**
   `map-techno-imdf-data.js` 재생성, 두 사본 동기화, 전체 회귀 확인.

## 6. 위험 요소

**도면틀 기준점 검출 실패 가능성.**
7개 층이 도면틀을 공유한다는 전제로 변환을 1개만 쓰는데, 페이지별 렌더링 여백이
미세하게 다르면 층이 통째로 어긋난다. 완화책: 층마다 치수선 좌하단 교점을 검출해
오프셋을 보정하고, 4.2의 층간 정합 검사(계단·엘리베이터 ±2m)로 반드시 확인한다.
이 검사가 실패하면 해당 층은 수동 정렬로 전환한다.

**엑셀 방 수가 도면 판독 범위보다 많다.**
엑셀 1F 76개·4F 82개인데 도면에서 확인된 번호 범위는 101~160, 401~466이다.
도면에 없는 방이 존재하거나 작은 글씨를 놓쳤을 수 있다. 2단계에서 실측 확인하고,
끝내 도면에 없는 방은 지도에서 제외하되 목록으로 명시 보고한다.
`테크노관1층.pdf`(비채)와 `테크노관3층(참고용).pdf`, `테크노관2,3층.pdf`,
`테크노관2,4층.pdf`, `테크노관1,2층.pdf`를 교차 확인용으로 활용한다.

**정사영상 해상도 한계.**
테크노관을 덮는 최고 해상도가 z16 ≈ 0.96 m/px이므로 좌표 정확도 한계는 **±1~2m**다.
층별 실내 표시 용도로는 충분하나 그 이상의 정밀도는 이 데이터로 달성할 수 없다.

**도면이 래스터다.**
벡터 CAD가 아니라 200dpi 스캔이므로 벽 두께·미세 형상은 근사가 된다. 400dpi로
렌더링해도 원본 해상도 이상의 정보는 없다.

**중복 사본.**
`GUMAP-프론트/js/map/`과 `GUMAP-일반지도/map/`의 파일 이원화가 이미 존재한다.
갱신 누락 시 어느 쪽이 반영됐는지 혼선이 생긴다 (3.8 참조).

## 7. 완료 기준

- 엑셀 361개 방 중 도면에 실재하는 방 전량이 실제 도면 형상 폴리곤으로 존재한다
  (도면에 없어 제외한 방은 목록으로 명시)
- 모든 폴리곤이 5점 직사각형이 아니다 (실제 벽 형상 반영 확인)
- `footprint` / `level` 도형이 실제 중정형 외곽선이다
- 4.2의 자동 검증 항목이 전부 통과하거나, 통과하지 않는 항목은 사유가 기록되어 있다
- 정사영상 위에서 건물 외벽과 폴리곤 외곽이 육안으로 일치한다
- `map-techno-indoor.js` 무수정 상태로 층 전환·검색·팝업·길찾기가 동작한다
