# 📋 GuMap 건물 라벨/태그 전수 표출 작업 진행 상황 및 인수인계 가이드

> **작성 일시**: 2026-09-12 (새벽)  
> **프로젝트**: GuMap (구미시 통합 모빌리티 지도)  
> **현재 작업**: 구미·김천·칠곡 전역 건물(학교·아파트·빌라·랜드마크) 줌 계층형 라벨 태그 표출 작업

## 1. 📌 현재 작업 내용 요약
* **목표**: 지도에 모든 건물(학교, 아파트, 빌라/연립주택, 공공기관 등)에 한눈에 알아볼 수 있는 명칭 태그(라벨 뱃지)를 붙이는 작업
* **기존 진행된 작업 파이프라인**:
  1. `GUMAP-개발/extract_all_buildings_hierarchy.py`: `(연속수치지형도)건물_경북.zip` 내 SHP/DBF에서 구미/김천/칠곡 건물 전수 추출
  2. `GUMAP-개발/extracted_buildings_full.json`: 추출된 학교, 아파트, 빌라 데이터셋 (약 4,700여 개)
  3. `GUMAP-개발/build_master_buildings_js.py`: 기존 거점 시설(92개) + 학교(329개) + 아파트(417개) + 빌라(3,931개) 통합
  4. `GUMAP-프론트/js/map/gumi-buildings-labels.js`: 줌 계층화 렌더러 생성 (현재 index.html에 로드됨)

---

## 2. 🚨 무한 로딩(멈춤) 발생 원인 분석

### 원인 A. 파이썬 추출 스크립트의 대용량 루프 동결 (`extract_all_buildings_hierarchy.py`)
* **상황**: `(연속수치지형도)건물_경북.zip` 내부의 `N3A_B0010000_47_A.dbf`(1,007MB)와 `47_B.dbf`(1,001MB)는 합쳐서 **2GB가 넘는 수백만 건**의 파일입니다.
* **이유**: 스크립트가 1GB짜리 DBF/SHP 바이너리를 한꺼번에 읽고, 수백만 건을 순수 파이썬 루프(`for i in range(num_records)`)로 돌면서 문자열 디코딩, 정규식, EPSG:5179 ➔ 4326 좌표 변환을 처리하여 콘솔 출력이 멈춘 채 **수십 분 이상 무한 대기(Hang)** 상태가 발생했습니다.

### 원인 B. 프론트엔드 지도 렌더러의 DOM 마커 과부하 (`gumi-buildings-labels.js`)
* **상황**: 빌라/맨션까지 총 4,700여 개의 마커 데이터가 하나의 자바스크립트 파일에 하드코딩되어 있습니다.
* **이유**: 지도에서 줌 레벨 16~17 이상으로 이동할 때 `updateBuildingLabelsVisibility()` 함수가 한 번에 수백 개의 HTML DOM 요소(`L.divIcon`)와 `L.marker` 인스턴스를 동적으로 생성/배치하면서 **브라우저 메인 스레드가 멈추거나 화면이 버벅이는 현상**이 발생합니다.

## 3. 🛠️ 내일 바로 이어서 작업하는 해결 순서

### Step 1. 이미 추출된 데이터 확인 및 즉시 활용
* 이미 `GUMAP-개발/extracted_buildings_full.json`과 `gumi-buildings-labels.js`가 빌드되어 있습니다.
* 무거운 파이썬 스크립트를 처음부터 다시 돌릴 필요 없이, 현재 생성된 `gumi-buildings-labels.js`의 프론트엔드 렌더링 성능만 최적화하면 바로 부드럽게 작동합니다.

### Step 2. 프론트엔드 렌더러 최적화 방안 (내일 AI에게 요청할 내용)
* 지도 이동/줌 변경 시 `L.marker`를 무더기로 생성하는 대신, 아래 방법 중 하나를 적용하도록 요청하세요:
  1. **화면 뷰포트 내 최대 렌더링 개수 제한 강화** (예: 화면당 최대 80~120개만 선별 표출)
  2. **그리드 기반 공간 인덱싱(Grid Index)** 적용으로 4,700개 순회 시간 0ms로 단축
  3. **Canvas 텍스트 레이어**로 일괄 렌더링하여 DOM 부하 0% 달성

## 4. ❓ "지금 난 MCP 에러"는 무엇인가요?

* **발생 원인**:
  * AI가 사용자의 브라우저(`http://localhost:3000/`) 화면 상태와 콘솔 에러를 직접 확인하기 위해 **`browser_subagent` (내부적으로 `chrome-devtools-mcp` 사용)**를 실행했습니다.
  * 이때 시스템의 크롬 브라우저 원격 디버깅 포트 연결이 일시적으로 거부되거나 타임아웃이 발생하여 IDE 인터페이스에 **MCP 관련 에러 알림**이 표시된 것입니다.
* **영향 여부**:
  * 이는 **AI 보조도구의 브라우저 제어 기능에 대한 일시적 통신 오류**일 뿐이며, **사용자 프로젝트 코드나 웹사이트, 파이썬 스크립트에는 아무런 문제가 없으니 안심하셔도 됩니다.**
