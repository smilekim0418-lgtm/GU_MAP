# 2026학년도 AX 기반 역량 강화 팀 프로젝트 계획서 [별지 6]

**선택 주제**: (20) AI 기반 구미 지역 모빌리티 서비스
**프로젝트명**: GUMAP — 정류장에서 강의실 문 앞까지, 실내외가 끊기지 않는 구미형 모빌리티 플랫폼

## 1. 프로젝트 목표

### □ 단기목표 (2026.09.11. ~ 2027.01.08.)

기존 지도 서비스의 안내는 정류장이나 건물 앞에서 끝나 정작 목적지인 강의실을 찾지 못하는 한계가 있음. 본 프로젝트는 이 **"마지막 100m"** 문제를 해결하기 위해, **금오공과대학교 테크노관을 첫 대상으로 지하 1층부터 6층까지 전 층의 실내지도와 실내 길찾기를 구축하고, 그 구축 과정을 AI로 자동화하여 캠퍼스 전체와 구미시 대중교통까지 확장**하는 것을 단기 목표로 함.

- **① 테크노관 실내지도 및 실내외 연속 길찾기 구축 (1차 목표)**
  - 테크노관 지하 1층~지상 6층 전 층의 건축 도면을 위경도 좌표에 정합하고, 강의실·연구실·실습실 등 각 실의 영역과 출입문을 데이터화함.
  - 계단·엘리베이터를 층간 이동 경로로 연결하고 건물 출입구를 실외 도보망과 이어, 건물 밖에서 강의실 문 앞까지 끊기지 않는 안내를 구현함.
  - 결과물은 국제표준 실내공간정보 형식(IMDF)으로 산출하여 이후 확장과 외부 활용이 가능하도록 함.

- **② 도면 → 실내지도 변환의 AI 자동화 (핵심 목표)**
  - 테크노관 구축 과정에서 도면 속 실 번호와 실명을 읽어내고 대조하는 작업은 사람이 일일이 확인해야 하는 병목이며, 이 상태로는 다른 건물로 확장하기 어려움.
  - 테크노관에서 확정된 실 정보를 정답 데이터로 삼아 OCR·객체 검출 모델을 학습시키고, 실 번호·벽선·출입문 인식을 자동화함.
  - 확신이 낮은 항목만 사람이 확인하는 **AI 초안 + 사람 검수** 구조로 전환하여 건물 1개 동 구축에 드는 시간을 대폭 단축함.

- **③ 캠퍼스 실내지도 확장**
  - 자동화된 파이프라인을 디지털관·글로벌관·중앙도서관·학생회관 등에 적용하여 **테크노관 포함 3개 동 이상**으로 확대하고, 건물 간 실외 보행망을 연결해 캠퍼스 전역의 연속 길찾기를 완성함.

- **④ 구미시 대중교통과의 완전 연결**
  - 시내버스 실시간 위치·도착정보, 대학 셔틀, 행복버스(DRT), 공유 PM을 실내 경로와 하나로 이어, **"정류장 → 버스 → 캠퍼스 도보 → 건물 출입구 → 층 이동 → 강의실 앞"** 을 한 번의 안내로 제공함.
  - 동일 노선인데 상행·하행이 별개로 표출되어 혼란을 주는 문제도 노선 정규화로 해소함.

- **⑤ 자연어 대화형 안내**
  - "테크노관 302호 어떻게 가?", "지금 도서관에서 구미역 가는 제일 빠른 방법"과 같은 질의를 거대언어모델(LLM)이 해석해 경로·버스·실내 안내 기능을 스스로 호출하고 결과를 지도에 표출함.

- **⑥ 지역 특화 경로 추론 AI 적용**
  - 구미시 도로망에 경사도·보도 여부·시간대별 혼잡 이력을 반영한 경로 추론 모델(GNN·강화학습)을 학습하여 경량 추론 형태로 서버에 탑재함.

- **⑦ 실증**
  - 재학생 100명 이상을 대상으로 실사용 베타 테스트를 진행하고, 현장 실측으로 실내 위치 정합 오차와 정류장 매칭 오차를 보정함.

**□ 정량 목표(KPI)**

| 구분 | 지표 | 목표 |
|---|---|---|
| 실내지도 구축 | 테크노관 실내지도 완성도 | **지하 1층~6층 전 층, 실 단위 95% 이상** |
| 실내지도 확장 | 실내지도 구축 건물 수 | **3개 동 이상** |

| 길찾기 | 실내외 통합 경로 탐색 응답시간 | **1초 이내** |

### □ 장기목표

- **(교내 확산)** 캠퍼스 전 건물로 실내지도를 확대하고, 신입생 오리엔테이션·강의실 안내·시설 예약·학사 정보와 연계하여 금오공과대학교 공식 캠퍼스 안내 서비스로 정착시킴.
- **(지역 확산)** 구미시 교통행정 부서 및 버스정보시스템(BIS) 운영 주체와 연계해 대시민 서비스로 확장하고, 시청·터미널·역사·복지관 등 공공시설 실내지도로 적용 범위를 넓힘.
- **(기술 자산화)** 도면→실내지도 자동 변환 파이프라인을 오픈소스로 공개하고, 실내외 통합 경로 탐색 기법을 학술 발표·소프트웨어 저작권 등록으로 자산화하여 타 대학·타 중소도시가 그대로 이식할 수 있는 표준 모듈로 발전시킴.
- **(AX 확산)** 프로젝트에서 축적한 AI 활용 개발 방법론을 교내 구성원과 공유하여 학내 AX 전환의 실증 사례로 기능하게 함.

## 2. 프로젝트 추진 방법

### 가. 세부 수행 방법 및 절차

**"테크노관에서 먼저 만들어 보고 → 그 과정을 AI로 자동화하여 → 다른 건물과 지역으로 확장한다"** 는 흐름으로, 4단계·2주 단위 스프린트로 진행하며 매 스프린트마다 실제 동작하는 산출물을 남김.

**[1단계] 테크노관 실내지도 구축 (1~8주차)**
- 대학 시설 관련 부서 협조로 테크노관 건축 도면을 확보하고, 도면 이미지에서 실 영역과 벽선을 추출함.
- 도면을 위경도 좌표계에 정합(Georeferencing)하되, 층마다 도면 축척과 기준점이 다르므로 층별로 개별 보정하여 층간 어긋남을 제거함.
- 각 실의 실 번호·실명·출입문 위치를 라벨링하고, 국제표준 실내공간정보 형식(IMDF)으로 변환함.
- 복도·계단·엘리베이터를 이동 경로로 연결해 실내 길찾기 경로망을 생성하고, 보행 속도와 층간 이동 시간을 반영한 소요시간 모델을 적용함.
- 도면만으로는 알 수 없는 실제 통행 제약(예: 특정 실은 다른 실을 거쳐야 진입 가능)은 현장 확인을 거쳐 경로망에 반영함.
- 건물 출입구를 실외 보행망과 연결하여 실내외 연속 길찾기를 1차 완성하고, 현장 실측으로 위치 오차를 보정함.

**[2단계] 도면 해석의 AI 자동화 (9~12주차)**
- 1단계에서 확정된 테크노관 전 층의 실 정보를 **학습·검증용 정답 데이터**로 정제하고, 구축 공정별 소요시간과 수작업 비중을 측정해 자동화 효과를 비교할 기준선을 확정함.
- 도면에서 실 번호·실명·벽선·출입문을 인식하는 모델을 학습·평가함.
- 인식 결과에 신뢰도를 부여해 확실한 항목은 자동 반영하고 애매한 항목만 편집 도구에 표시해 사람이 확인하며, 검수 결과를 다시 학습에 환류해 정확도를 누적 개선함.
- 강의실 대장(엑셀)과 자동 대조하여 실 번호 누락·중복·불일치를 즉시 검출하는 검수 체계를 갖춤.
- 테크노관에 맞춰진 설정(도면 축척·기준점·실 번호 규칙)을 건물별 설정으로 분리하여, 새 건물은 도면과 설정만으로 추가되는 구조로 일반화함.

**[3단계] 건물 확장 및 대중교통 통합 (12~15주차)**
- 자동화된 파이프라인을 디지털관·글로벌관·중앙도서관·학생회관 등에 순차 적용하고, 수작업 대비 소요시간 단축 효과를 측정함.
- 건물 간 실외 보행망을 연결해 캠퍼스 전역 경로망을 하나로 병합함.
- 구미시 시내버스·셔틀·행복버스·공유 PM을 실내 경로와 결합해 하나의 경로 결과로 이어지도록 경로 탐색기를 확장하고, 상·하행 노선 정규화를 적용함.

**[4단계] AI 계층 고도화·실증·마무리 (14~18주차)**
- 자연어 질의 해석 모듈과 지역 지리 사전을 구축하고, 경로 추론·버스 도착예측 모델을 학습해 서버에 탑재함.
- 기존 알고리즘·상용 API와 성능을 비교 검증하고, 재학생 베타 테스트 결과를 반영해 개선함.
- 접근성(휠체어 경로·고대비·음성 안내)과 개인정보 처리 점검을 거쳐 최종본을 확정함.

**□ 협업 운영 방식**
- **개발 협업**: GitHub 단일 저장소를 사용하며, 기능별 브랜치 → Pull Request → 상호 코드리뷰 승인 후 병합을 원칙으로 함. 모든 작업은 이슈로 등록해 담당자와 마감일을 명시함.
- **회의 운영**: 주 1회 정기 회의와 2주 단위 스프린트 리뷰를 운영하고 회의록을 축적함. 운영 회의비(팀당 50만원)는 정기 회의 및 현장 실측 조사에 집행하고 지출 내역을 별도 관리함.
- **품질 관리**: 실내지도 빌드 결과와 화면 동작을 검증하는 자동 테스트를 구축·운용하며, 통과하지 못한 변경은 병합하지 않음.
- **문서·지식 공유**: 공유 워크스페이스에 회의록·설계 문서·데이터 카탈로그·API 키 관리 규정·실험 결과를 축적하여 팀원 전원이 같은 맥락에서 작업함.
- **보고서 작성**: 월별 활동보고서(팀·개인)는 팀장이 총괄하되 각자 담당 파트를 작성하고, 지도교수 피드백을 반영해 기한 내 제출함.

### 다. 지도교수 지도 계획

- **정기 지도회의(격주 1회, 총 8회 내외)**: 스프린트 산출물을 실제로 시연하며 기술적 타당성과 진척도를 점검받고 다음 목표를 확정함.
- **연구 방향 지도**: 도면 인식 모델의 평가 지표 설정, 실내외 통합 경로 탐색의 알고리즘적 타당성, 성능 비교 실험 설계를 지도받아 결과물이 단순 구현을 넘어 검증 가능한 성과가 되도록 함.
- **데이터·현장 협조 지원**: 테크노관을 비롯한 대상 건물의 건축 도면 및 강의실 대장 확보, 학내 실증 승인, 구미시 관련 부서 협의 등 학생 단독으로 어려운 절차를 지도교수의 협조 요청을 통해 진행함.
- **외부 전문가 자문 활용(팀당 최대 2회)**
  - **1회차(10월 중)**: 건축·BIM 또는 실내공간정보(IMDF) 분야 전문가 — 도면 정합 방식과 실내지도 데이터 품질 기준 자문.

### □ AI가 수행하는 핵심 기능 및 적용 필요성

**① 건축 도면의 실내지도 자동 변환 — 본 프로젝트 AX의 핵심**
- **기능**: 도면 이미지에서 실 번호·실명·벽선·출입문을 인식해 실내지도와 길찾기 경로망의 초안을 자동 생성하고, 확신이 낮은 항목만 사람이 검수함.
- **적용 필요성**: 실내지도 구축의 실질적 비용은 도면 판독과 실 번호 대조에 집중되며, 이를 사람이 전부 처리하면 건물 한 개 동에도 상당한 시간이 소요되어 캠퍼스 전체 확장이 사실상 불가능함. 본 프로젝트는 테크노관을 먼저 사람 손으로 구축하여 **정확한 정답 데이터와 소요시간 기준선을 동시에 확보**한 뒤, 그 데이터로 인식 모델을 학습시키는 방식을 취함. 따라서 학습 자료 확보가 보장되고, AI 도입 효과가 "인식률"과 "소요시간 단축률"이라는 정량 지표로 직접 측정되는 구조임.

**② 자연어 대화형 모빌리티 안내 (LLM + RAG)**
- **기능**: "테크노관 302호 어떻게 가?"와 같은 질의에서 목적지·출발지·이동수단 선호를 구조화된 값으로 추출하고, 실내 경로 탐색·버스 조회·장소 검색 기능을 스스로 호출해 결과를 지도에 표출함.
- **적용 필요성**: 실내지도가 아무리 정밀해도 사용자가 "몇 층 몇 호"를 정확히 알아야만 쓸 수 있다면 신입생·방문객에게는 소용이 없음. 강의실을 "전자공학 실습실", "3층 컴퓨터실"처럼 부르는 실제 표현의 변형은 규칙 기반 처리로 감당할 수 없어 언어 이해를 담당하는 LLM이 필요함. 다만 LLM은 테크노관 실 번호 체계를 모르므로, 자체 지리 사전을 검색증강생성으로 주입해 잘못된 답변을 억제함.

**③ 지역 특화 경로 추론 (GNN + 강화학습)**
- **기능**: 도로·보도 구간의 경사도, 시간대별 혼잡 이력 등을 학습해 통행 적합성을 추론하고, 환승 대기와 층간 이동 비용까지 반영한 경로를 산출함.
- **적용 필요성**: 전국 표준 상용 API는 대학 셔틀·교내 보행로·건물 내부를 반영하지 못하며 호출량에 비례한 비용이 발생해, 공공 서비스로 확장할수록 부담이 커짐. 자체 추론 모델을 확보해야 지역 특성 반영과 비용 지속가능성을 함께 달성할 수 있음.

**④ 버스 도착 예정시각 보정 (시계열 예측)**
- **기능**: 시간대·요일·강수 여부·정류장 순번과 원천 도착정보를 입력으로 실제 도착 시각을 예측해 안내값을 보정함.
- **적용 필요성**: 원천 API의 도착 예측은 거리 기반 단순 계산에 가까워 등하교 시간대와 악천후에 오차가 크게 벌어지며, 이는 대중교통 불만족의 핵심 원인인 대기 스트레스와 직결됨. 과거 운행 실적의 패턴 학습은 통계적 규칙보다 신경망이 우수하므로 시계열 딥러닝 적용이 타당함.

**⑤ AI 코딩 에이전트를 활용한 개발 프로세스 자체의 AX**
- **기능**: 코드 생성·리팩터링·테스트 작성·코드리뷰·문서화에 AI 코딩 에이전트를 상시 활용하고, 팀 내 프롬프트와 활용 사례를 공유 자산으로 축적함.
- **적용 필요성**: 소수 인원의 학부생 팀이 4개월 안에 실내지도 구축·AI 모델 학습·대중교통 통합·모바일 앱을 모두 완성하려면 개발 생산성 자체를 끌어올려야 함. 동시에 이 과정은 팀원 전원이 "AI를 쓰는 개발자"로 성장하는 훈련이 되어 본 사업 취지에 직접 부합함. 다만 AI가 생성한 코드는 반드시 상호 리뷰와 자동 테스트를 통과시켜 검증 없는 수용을 방지함.

| 구미시 사회조사 통계, 인구 현황 | KOSIS 국가통계포털, 구미시 통계자료 | 공개 통계표 다운로드 | 문제 정의 근거, 수요 분석 |
| 서비스 이용 로그(경로 요청·검색어) | 자체 서비스 수집 | 이용자 사전 동의 후 익명 수집 | 사용성 개선, 인기 경로 분석, 모델 재학습 |
| 베타 테스트 설문·현장 실측 데이터 | 자체 수집 | 재학생 대상 설문 및 현장 실측 조사 | 위치 오차 보정, KPI 측정, 개선 우선순위 도출 |

**□ 데이터 관리 원칙**
- 공공데이터는 각 기관의 이용약관과 출처 표시 조건을 준수하며, 라이선스와 출처를 데이터 카탈로그에 명시함.
- **캠퍼스 건축 도면은 시설 보안과 직결되므로 학내 승인 범위 내에서만 사용하고, 기계실·전기실 등 보안이 필요한 구역은 공개 산출물에서 제외하거나 상세 정보를 비표시 처리함.**
- 이용 로그는 개인 식별정보를 수집하지 않고 즉시 비식별 처리하며, 수집 항목·목적·보관기간을 서비스 내에 고지하고 동의를 받은 경우에만 저장함.
- API 인증키는 저장소에 포함하지 않고 환경변수로 분리 관리하여 유출을 방지함.

## 6. 기대효과

**□ 학습 효과 — AX 기술에 대한 실무적 이해**
- 종이 도면이라는 비정형 자료를 좌표계로 정합하고, 경로망으로 구조화하고, 컴퓨터비전으로 해석하여, 최종적으로 사용자의 질문에 답하는 서비스가 되기까지 **데이터가 형태를 바꾸며 흐르는 전 과정**을 직접 수행함. 이는 AX의 본질인 "현장에 흩어진 비정형 자료를 AI가 다룰 수 있는 데이터로 바꾸는 일"을 그대로 경험하는 것임.
- LLM 활용에 그치지 않고 컴퓨터비전·그래프 신경망·강화학습·시계열 등 과제 성격에 맞는 모델을 선택하고 검증하는 경험을 통해 "AI를 쓰는 능력"과 "AI를 만드는 능력"을 함께 확보함.
- **먼저 사람 손으로 해본 뒤 같은 일을 AI로 대체하는 순서**로 진행하므로, 자동화 전후를 직접 비교하며 AI 도입 효과를 막연한 기대가 아닌 측정된 수치로 이해하게 됨.

**□ 문제 해결 능력 강화 — 협업 및 리더십 경험**
- 기획·발표, 지도 구현, IMDF 구축, 데이터 전처리로 역할이 나뉘어 있으나 하나의 경로 결과를 만들려면 네 파트가 모두 맞물려야 하므로, 실질적 협업 없이는 완성이 불가능함. 코드리뷰·스프린트·자동 테스트로 결합하는 실제 소프트웨어 팀 개발을 경험함.
- 도면이라는 현실의 불완전한 자료(누락된 실 번호, 도면과 다른 실제 동선)를 다루며, 교과서적 조건이 주어지지 않은 문제를 정의하고 정량 지표로 해결을 입증하는 접근법을 훈련함.
- 지도교수 지도와 외부 전문가 자문, 재학생 베타 테스트를 거치며 개발자의 가정과 실제 사용자·현장 전문가의 필요가 어떻게 다른지 확인하고 설계를 수정하는 경험을 함.

**□ 확산 가능성 — 교내 AX 활성화 기여**
- 테크노관에서 검증하고 자동화한 파이프라인은 **건물과 학교를 바꿔도 도면과 설정만 있으면 동작**하므로, 교내 타 건물·타 대학·공공시설로 즉시 확장 가능함.
- 국내 대학 캠퍼스는 상용 지도조차 실내 정보를 제공하지 않는 공백 지대이며, 본 성과는 그 공백을 메우는 선도 사례로서 타 대학이 참조할 수 있는 모델이 됨.
- 소스코드·기술 문서·데이터 형식을 공개 형태로 정리해 후속 팀이 이어받을 수 있게 하고, 개발 과정에서 축적한 AI 활용 노하우를 학과 세미나·교내 발표로 공유하여 다른 구성원이 자기 분야에 AI를 적용하는 출발점을 제공함.

**□ 대학 및 지역사회 기여**
- 신입생·편입생·외국인 유학생·외부 방문객이 강의실과 시설을 찾지 못해 겪는 어려움을 실질적으로 해소하여 대학의 정주 여건과 방문객 편의를 개선하고, 학사·시설 안내 문의에 드는 행정 부담을 줄임.
- 대중교통 안내가 정류장에서 끊기지 않고 목적지 문 앞까지 이어지는 **"마지막 100m" 해결 모델**을 제시하여, 지방 중소도시형 모빌리티 서비스(MaaS)의 실증 사례가 됨.
- 축적된 이동 수요 데이터는 향후 대학 셔틀 노선 조정, 캠퍼스 시설 배치, 지자체 교통 정책 수립의 근거 자료로 활용 가능함.
